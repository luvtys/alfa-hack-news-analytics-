# ALFA BUSINESS × TWILIGHT
## Новостная аналитика для принятия бизнес-решений

Интеллектуальный сервис для руководителей крупного бизнеса, который превращает поток внешних новостей и аналитики Альфа-Банка в персонализированные бизнес-инсайты. Сервис определяет контекст компании, отбирает значимые события и объясняет их влияние с учетом внешних источников и экспертизы банка.

---

## 1. Аннотация и цель проекта

Крупные компании работают с большими объемами информации, и руководителю важно не просто узнать новость, а понять, как она повлияет на его бизнес. Наш сервис решает проблему «информационного шума»: мы не пересказываем новости, а даем персонализированную интерпретацию события, риски, возможности и рекомендации, опираясь на данные компании и аналитику Альфа-Банка.

Сервис реализует полный цикл обработки:
1. Получение события (в прототипе — через API).
2. Детерминированный скоринг (отсев нерелевантных новостей без затрат токенов LLM).
3. Поиск релевантной аналитики банка (RAG).
4. Генерация инсайта (что произошло, почему это важно, риски, возможности, рекомендации).
5. Отображение в интерфейсе, похожем на интернет-банк.

## 2. Архитектура решения

```text
[Новость]
    │
    ▼
[Скоринг (scoring/scenarios.yaml)] ──► 0 токенов, отсеивает нерелевантные события
    │ (если passed)
    ▼
[RAG (rag.py)] ──► Поиск по аналитическим материалам Альфа-Банка (ChromaDB)
    │
    ▼
[Агент (agent_core.py)] ──► Сборка инсайта по контракту insight.schema.json
    │
    ▼
[FastAPI (main.py)] ──► Отдача JSON и раздача статики фронтенда
    │
    ▼
[Frontend (frontend/)] ──► UI с лентой, трассировкой, ролями и чатом
```

### Ключевые архитектурные решения

-   **Экономия бюджета LLM.** Модель вызывается только для событий, прошедших скоринг. Для остальных — 0 токенов.
-   **Отказы (Guards).** Если данных недостаточно (например, покрытие выручки < 20%), система честно отказывается от вывода (критерий приемки №2).
-   **Трассировка.** Пользователь видит этапы самопроверки ИИ (шаги 7–9) и может понять, как был сделан вывод.
-   **Отказоустойчивость.** Если LLM недоступна или выдает невалидный ответ, система использует заготовленный аналитический шаблон, чтобы пользователь всегда видел результат.

## 3. Как запустить проект

### Вариант 1: Через Docker (рекомендуется)

Убедитесь, что у вас установлен Docker Desktop.

1. Создайте файл `.env` в папке `backend`:
   ```env
   OPENAI_BASE_URL=https://changellenge.up.railway.app/v1
   OPENAI_API_KEY=ваш_ключ_из_чата_хакатона
   ```
2. Перейдите в папку `backend` и запустите:
   ```bash
   cd backend
   docker-compose up --build
   ```
3. Откройте в браузере: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)

### Вариант 2: Локальный запуск (Python 3.11+)

1. Установите зависимости:
   ```bash
   cd backend
   pip install -r requirements.txt
   ```
2. Создайте `.env` в папке `backend` (как в варианте 1).
3. Соберите векторную базу (RAG). Это нужно сделать один раз:
   ```bash
   python rag.py
   ```
4. Запустите сервер:
   ```bash
   python main.py
   ```
5. Откройте в браузере: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)

## 4. Бэкенд (`backend/`)

### Технологии
- Python 3.11, FastAPI, Uvicorn
- Pandas, PyArrow (работа с витриной данных parquet)
- ChromaDB, Sentence-Transformers (RAG)
- OpenAI SDK (работа с LLM через совместимый API)
- Qwen3.6 35B A3B (разрешенная модель)

### Структура
```text
backend/
├── main.py            # FastAPI: ручки /api/insight, /api/feed, /api/chat
├── agent_core.py      # Логика агента: скоринг → RAG → сборка инсайта
├── rag.py             # Векторный поиск по аналитике банка
├── scoring/           # Замороженный скоринг от БА (scenarios.yaml)
├── contracts/         # Схемы ответов (insight.schema.json)
├── prompts/           # Промпты от БА
├── datamart/          # Витрина данных (parquet)
├── data/              # Тексты аналитики для RAG
├── Dockerfile
── docker-compose.yml
```

### Ключевые ручки API
- `POST /api/insight` — генерация инсайта для одного события.
- `POST /api/feed` — лента новостей (9 событий, прогоняются через агента).
- `POST /api/chat` — уточняющий вопрос по инсайту.

### Особенности реализации
- Скоринг возвращает список сценариев, отсортированных по баллам. Если ни один не прошел порог, возвращается `skipped`.
- RAG ищет релевантные фрагменты в аналитике банка и очищает текст от таблиц и английских обрывков.
- Сборка инсайта формируется на основе профиля компании и результатов скоринга.
- Чат отвечает на вопросы про риски, возможности, действия и ставку на основе данных инсайта (мгновенно, без затрат токенов).

## 5. Фронтенд (`frontend/`)

### Технологии
- HTML5, CSS3, Vanilla JS (без фреймворков)
- Canvas API (анимации тумана и параллакса)

### Что реализовано (по ТЗ)
- Экран входа (точка входа в сервис).
- Смена ролей (CFO, Собственник, Главбух) — вывод меняется под каждую роль.
- Лента инсайтов с перелистыванием (стрелки по бокам карточки).
- Карточка инсайта:
  - Скрытый сигнал (почему это важно для компании).
  - Угрозы и возможности.
  - Мнение Альфа-Банка с цитатой и бейджами (AI / Аналитика).
- Экран отказа («Вывод не сделан») — если сработал guard.
- Экран пустой ленты («Пока всё стабильно») — если новость не прошла скоринг.
- Трассировка («Путь ИИ») — шаги с самопроверкой (шаг 7 — ошибка, шаг 8 — исправление).
- Чат («Спросить») — можно задать вопрос по инсайту.

## 6. Бизнес-аналитика (`docs/`, `scoring/`, `contracts/`)

Бизнес-аналитики команды подготовили:
- `contracts/insight.schema.json` — замороженный контракт между бэком и фронтом.
- `scoring/scenarios.yaml` — конфиг скоринга (веса, пороги, guard-ы).
- `prompts/` — системные промпты для агента.
- `golden/golden_set.yaml` — golden set для проверки качества.
- `HANDOFF.md` — передача решений в разработку.

## 7. Тестирование

В папке `backend` есть скрипты для проверки:

```bash
python check_backend.py                    # проверка генерации инсайта
python check_skip.py                       # проверка отказа (0 токенов)
python golden/golden/run_golden.py \       # Golden Set от БА
  --datamart datamart/datamart/out \
  --scoring scoring/scoring
```

### Результат Golden Set
```text
верно сработал 9, верно промолчал 11, ложных срабатываний 0, пропусков 0
точность 1.00, полнота 1.00, F1 1.00
```

## 9. Сценарий проверки

1. Откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/).
2. Нажмите **«Begin Analysis»**.
3. Переключите роль на **«Финансовый директор»** — появится лента инсайтов (листается стрелками).
4. Переключите на **«Собственник»** — появится экран отказа (покрытие < 20%).
5. Переключите на **«Главный бухгалтер»** — появится экран «Пока всё стабильно» (ниже порога).
6. Задайте вопрос в чате (**«Какой риск?»**) — получите мгновенный ответ.
