# Контракт 1.1.0 — что кому отправлять

Заморожен 20 октября 2026, одно изменение 21 октября — решение команды по
критерию приёмки 2: при недостаточном покрытии система отказывается от
вывода, а не показывает предупреждение. Что именно поменялось, перечислено в
начале `api_contract.md`. Дальше бэк и фронт снова могут работать
параллельно и не встречаться до среды.

```
insight.schema.json      схема одного инсайта (JSON Schema 2020-12)
trace.schema.json        схема хода рассуждения агента
api_contract.md          три эндпоинта, конверты ответов, коды ошибок
validate_contract.py     проверка фикстур; ставится в CI
fixtures/                пять ответов ленты и одна трасса на реальных компаниях
```

Из пяти фикстур две — не инсайты, и они важнее остальных для фронта:
`insights_U_4601_CFO_empty.json` — релевантных событий не нашлось,
`insights_U_182712_CFO_blocked.json` — событие нашлось, но данных для вывода
недостаточно. Это два разных состояния, и они верстаются по-разному.

Проверка: `pip install jsonschema && python3 validate_contract.py`.
Сейчас проходит полностью.

## Бэкенду

1. Поднять витрину: архив `datamart.zip`, внутри `build_datamart.py`,
   `schema.sql` и `load.sh`. Три команды, около минуты.
2. Реализовать `/api/insights`, `/api/chat`, `/api/trace/{id}` ровно по
   `api_contract.md`. Отдавать `contract_version: "1.1.0"` в каждом ответе.
3. Поставить `validate_contract.py` в CI и прогонять на своих ответах, а не
   только на фикстурах.
4. Писать трассу с первого дня. Поля `tokens_in`, `tokens_out`, `cost_rub` —
   обязательные: по ним считается расход лимита в 500 рублей, и они же идут
   на слайд питча.
5. Инструменты, которые читают витрину напрямую и не требуют модели:
   `get_company_profile`, `get_group_profile`, `get_counterparties`,
   `get_affiliates`, `get_peer_stats`, `score_relevance`. Они закрывают
   большую часть ленты без единого токена.

## Фронтенду

1. Собирать вёрстку на фикстурах из `fixtures/`. Модель не нужна вообще.
2. Четыре обязательных состояния: лента с инсайтами, пустая лента с
   `empty_reason`, баннер `budget_exceeded`, ошибка. Пустая лента — не
   заглушка, а демонстрируемый сценарий: она доказывает, что система не
   срабатывает на всё подряд.
3. Бейджи источников по `evidence[].kind`. Четыре типа, четыре вида:
   данные банка, цитата аналитики с датой, внешняя ссылка, вывод модели.
   Последний визуально слабее остальных — именно он показывает жюри, что мы
   отделяем факты от интерпретации.
4. Блок «ход мыслей» — только из `/api/trace`. В фикстуре `trace_trc_8f21ab`
   есть шаг, где критик забраковал формулировку, и следующий, где аналитик её
   переписал. Это сильнейшие две строки во всём демо, их стоит раскрывать по
   умолчанию.
5. При `data_quality.flow_coverage_tier` равном `low` или `negligible`
   обязательно показывать примечание из `data_quality.notes` рядом с цифрами
   по контрагентам.

## Почему фикстуры именно такие

| Файл | Компания | Что проверяет |
| --- | --- | --- |
| `insights_U_106783_CFO.json` | производство распределительной аппаратуры, 20,8 млрд | полный инсайт: три последствия, мнение банка, допущение модели, высокое покрытие данными |
| `insights_U_26030_CFO.json` | опт моторным топливом, 60,4 млрд | сценарий стоимости долга, пять источников, цитата с датой |
| `insights_U_1941_CFO.json` | опт бытовыми товарами, 24,1 млрд | валютный сценарий при низком покрытии потоком — проверка примечания |
| `insights_U_4601_CFO_empty.json` | опт мясом, 16,9 млрд | пустая лента: агент проверил 214 событий и ничего не выдал |
| `trace_trc_8f21ab.json` | — | девять шагов, один цикл самокоррекции, расход токенов |

Все компании и все числа в профилях взяты из витрины, а не придуманы.
Новостные события — реальные публикации из корпуса аналитики Альфы с
указанием документа, страницы и даты.
