# Golden set и автопроверка

```
golden_set.yaml     20 пар «компания × событие» с эталонами
holdout.yaml        5 отложенных пар — не открывать до четверга
run_golden.py       прогон отбора; с --insights прогоняет и выдачу бэкенда
check_insight.py    автопроверка одного инсайта: ловит числа без источника
```

```bash
pip install pyyaml pandas pyarrow
python3 run_golden.py --datamart ../datamart/out --scoring ../scoring
python3 check_insight.py ../contracts/fixtures/insights_*.json
```

## Состав: почему именно так

Восемь пар, где система обязана сработать. Восемь, где обязана промолчать:
обзор рынка золота, спортивная новость, контрольная компания `U_4601` с
распылённой базой из 329 плательщиков, и `U_234228` с выручкой 56,6 млрд,
которая не импортёр и потому валютный сценарий поднимать не должна.

И четыре ловушки — случаи, где наивная реализация сработает, а правильная
откажется. Они ценнее остальных шестнадцати.

**T01 — `U_182712`.** Топ-1 плательщик даёт 99,9% потока. Любая система
закричит о критической зависимости. Но банк видит 3,2% выручки, плательщиков
всего три, и вывод построен на одной тридцатой оборота. Guard по покрытию
блокирует сценарий и возвращает объяснение.

**T02 — `U_276153`.** Своих кредитных продуктов нет. Кредит есть у «группы»
из 482 юрлиц с неподтверждённой структурой. По такому признаку выводы о
долговой нагрузке делать нельзя.

**T03 — `U_106783`, роль главбуха.** Та же пара, что в P01, но множитель
роли опускает балл ниже порога. Проверка механики, а не текста.

**T04 — `U_1941`.** Правильный ответ с неправильным источником: прогноз
курса можно взять из документа от 7 сентября, который пересмотрен
11 сентября. Ответ будет выглядеть убедительно и будет неверным.

## check_insight: что именно ловится

Инсайт по контракту обязан сам перечислить всё, на чём построен:
`client.features_used`, `event.confirmed_facts`, `interpretation.bank_view`
и `data_quality`. Значит любое число в тексте, которого нет в этом перечне,
появилось из головы модели. Это и есть проверка П1.

Остальное: вывод без `evidence_ids` и ссылка на несуществующий источник
(П2), цитата аналитики без даты или из пересмотренного документа (П6),
формулировка «доля выручки» применительно к платежам и вывод о контрагентах
при низком покрытии (П4), упоминание пустого поля (П3), признак ключевого
собственника, поданный как риск (П5), вывод уровня группы при
неподтверждённой структуре (П8), и ролевое правило для главбуха.

Скрипт работает без моделей и без человека, ставится в CI и возвращает
ненулевой код при любой ошибке.

## Что нашлось при первом же запуске

Три нарушения в фикстурах, которые я сама и писала.

В инсайте по `U_26030` стояло «рыночная альтернатива стоит около 16%».
Числа 16 нет ни в одном объявленном источнике: в evidence объявлены
доходности 15,3%, 17,0% и 19,8%. Формулировка заменена на точную.

В инсайте по `U_1941` стояло «удорожание примерно на 16% за год и ещё на 6%
в следующем». Это модель поделила 13,0 на 11,2 — ровно то, что запрещает
П1. Расчёт вынесен в `alfa_corpus_facts.json` как готовое поле, число
приходит из справочника и объявляется фактом события.

В инсайте по `U_106783` встретился оборот «не по доле выручки». Смысл был
верный, но запрещённой формулировке незачем попадаться читателю на глаза.

И две ошибки в конфиге сценариев, которые нашёл сам golden set.

Сценарий спроса срабатывал на любом событии с типом `sector_demand`, включая
новость о падении инвестиций. Тип события оказался слишком грубым: спрос и
ФОТ — это про розницу, зарплаты и цены. Триггер переписан на сущности.

Компании со слабым сигналом концентрации отсекались фильтром аудитории и
исчезали молча. Теперь они доходят до сценария и блокируются guard-ом, то
есть в трассе видно «сигнал есть, но покрытие недостаточно». Для
демонстрации это разница между «система промолчала» и «система объяснила,
почему промолчала».

## Holdout

Пять пар в `holdout.yaml`. Файл открывается один раз, в четверг вечером,
после заморозки кода. Прогон делает один человек, результат записывается как
есть, включая провалы. Провал на holdout не чинится правкой конфига — он
фиксируется и объясняется на питче.

Если подкрутить пороги под holdout, критерий 05 перестанет чем-либо
подтверждаться, и это будет видно по первому же вопросу жюри.

## Когда поднимется бэкенд

```bash
python3 run_golden.py --datamart ../datamart/out --scoring ../scoring \
                      --insights backend_out/
```

Тогда прогон проверит не только отбор, но и содержание каждого выданного
инсайта. До этого момента отбор уже проверяем, а `check_insight` работает на
фикстурах контракта.
